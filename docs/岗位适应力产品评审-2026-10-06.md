# 岗位适应力产品评审

日期：2026-10-06。服务对象：中职学生、五年制高级工学生。

本次依据当前工作区的模型、路由、模板及 AI 提示词评审产品能力，包含现有未提交改动。未运行真实学生流程、付费模型或线下实训；功能存在不等于教学效果已验证。没有调整业务代码或业务数据。专业、合作企业和实际课程安排尚未明确，以下专业案例用于说明设计方式，不代表学校已有专业。

## 1. 判断与产品定位

平台已有求职训练基础，但距离岗位适应力培养，还缺少工作任务训练、线下实操证据和教师干预闭环。建议定位为“从求职到实习上岗的岗位适应训练平台”，面试是其中一个模块。

学生需要逐步做到：知道岗位做什么 → 能说清自己会什么 → 能听懂并确认任务 → 按要求完成工作 → 能交接、处理异常并主动求助 → 能根据反馈改进。

针对这类学生，应降低题目语言的抽象程度、缩小单次任务、增加示范和分步提示；专业标准应按具体工种、培养阶段和学校要求设置。高级工学生的专业操作要求不应简单等同于低年级中职，学历标签也不应被用于推断个人能力。

教育部对新版专业教学标准的说明强调职业综合素质、行动能力、模块化课程及实践教学；高级工课程还应参考人社部门相应工学一体化课程标准。这支持采用真实任务组织训练，但并不能证明本平台已经产生培养效果。

参考：[教育部新版专业教学标准说明](https://hudong.moe.gov.cn/jyb_xwfb/s271/202502/t20250211_1178747.html)、[人社部工学一体化课程标准通知](https://www.mohrss.gov.cn/xxgk2020/fdzdgknr/qt/gztz/202311/t20231115_509072.html)。中职与技工院校应分别对接适用标准及本校方案。

## 2. 现有能力与关键缺口

| 阶段 | 当前可确认的能力 | 对岗位适应力的缺口 |
|---|---|---|
| 岗位认知 | 企业及岗位介绍、目标岗位选择、匹配评估 | 缺少工作日常、工具、工作环境、任务及达标要求的结构化说明 |
| 求职准备 | 简历编辑、语音／文字面试、单题练习、三轮面试 | 仍有技术招聘偏向；缺少适合实训经历和首次求职的引导 |
| 训练反馈 | 总分、五维报告、逐题建议、参考回答、历史趋势 | 未考察与低表现混合；缺少明确补练任务和修改后的验证 |
| 学习提升 | 文章、测验、完成记录和测验尝试 | 内容学习尚未连接工作任务；阅读完成直接计 100 分 |
| 入职与工作 | 面试中可以问情境题 | 缺少有任务目标、材料、过程、交付物和验收规则的训练 |
| 教学组织 | 学生档案、教师查看、班级／系部画像、薄弱题聚合 | 缺少布置任务、教师反馈、退回重做、线下实操记录和导师观察 |

当前数据模型主要覆盖简历、面试、学习材料和练习记录，尚未发现任务提交、教师批注、工作作品和实习导师反馈的独立业务结构。

## 3. 现有功能需要先调整的地方

本报告中 P0 表示实现培养目标的前置基础，P1 表示近期扩展，P2 表示后续完善；不是线上故障等级。

### P0：评分与画像不能混淆“未评估”和“能力不足”

当前面试提示词要求未考察维度填 0，画像又会把数值分数纳入均值。文字说明不能阻止这个 0 被当成能力低分。不同岗位、轮次和模式的分数也会进入共同画像或排名，解释力有限。

调整建议：

- 每项能力保存“未评估／已有观察／需要补充证据”、表现等级、原始证据、是否使用提示及评价来源。
- 未评估用独立状态或空值表示，排除在均值之外；覆盖不足时不给完整胜任结论。
- 分开显示面试表现、情境任务表现、线下实操表现；允许同一能力在不同来源下结果不同。
- 成长比较至少保持岗位、任务类型、难度、提示条件和评价规则可比，并记录规则版本。
- 安全相关任务设置必须通过的关键项，不能用表达分或礼貌分抵消；具体标准由专业教师确认。

证据：[评分提示词](/Users/laozhenyu/Project/interview/app/services/interview_prompts.py:113)、[画像聚合](/Users/laozhenyu/Project/interview/app/routes.py:1234)、[排行榜](/Users/laozhenyu/Project/interview/app/routes.py:229)。

### P0：移除不适合目标学生的默认内容

报告页仍将复面称为“技术面”、终面称为“高管面”；下一轮开场同样使用这些称呼。能力页专业弱项推荐 Python／Java，链接为 `#`。岗位匹配提示词默认“技术招聘专家”。这些内容与通用的中职、技能岗位定位错位，即使核心面试提示词已经支持非技术岗位，也需要统一调整。

调整建议：

- 默认面试路线为“基础求职面试 → 岗位知识与实训经历 → 综合沟通”；按企业实际招聘流程配置轮次，不要求每个岗位三轮。
- 明确区分“模拟招聘轮次”和“培养训练阶段”，工作任务训练独立进入课程。
- 题目允许使用课堂、实训、技能比赛、兼职或实习经历，不默认有正式项目经历。
- 训练推荐按岗位和具体缺口生成，链接直接进入可执行任务。
- 简历优先展示专业技能、实训经历、证书、作品及承担过的具体工作；为缺少工作经历的学生提供逐步填写引导。
- 采用常用词和短句，每次一个问题；抽象术语附具体例子。

证据：[报告中的轮次名称](/Users/laozhenyu/Project/interview/app/templates/summary.html:102)、[下一轮开场](/Users/laozhenyu/Project/interview/app/api/interview.py:710)、[Python／Java 推荐](/Users/laozhenyu/Project/interview/app/templates/radar.html:147)、[技术招聘专家](/Users/laozhenyu/Project/interview/app/api/insights.py:302)。

### P0：把查看报告改成可以完成的复盘任务

学生打开报告即被标记为已复盘，没有验证其理解或修改。逐题反馈和“满分参考回答”可帮助学习，但也可能让学生只记答案。此处是产品风险，实际是否发生需要观察学生行为。

建议每次报告只突出一至两个可操作问题，例如“交接时漏了未完成事项”。学生确认改进点 → 重答或修订作品 → 做一个同能力的新情境 → 显示是否已改进。参考回答改为“示例与关键要点”，提醒使用真实经历；对开放题允许多个合理方案。

练习模式提供提示、解释和重做；测评模式固定规则并记录提示使用情况。正常暂停、网络故障、转写失败应与主动放弃区分，冷却限制不应挡住针对性补练。对学习中断原因的判断需有可靠流程，不能仅按超时推断。

证据：[打开报告即复盘](/Users/laozhenyu/Project/interview/app/routes.py:454)、[参考回答入口](/Users/laozhenyu/Project/interview/app/templates/summary.html:199)、[冷却与超时机制](/Users/laozhenyu/Project/interview/app/utils/session_state.py:1)。

### P1：调整学习与激励机制

文章完成接口直接记录 100 分，应改为“已阅读”；测验通过、任务完成、线下技能达标分别记录。知识测验用于检查理解，不能替代操作验收。

班级激励优先展示个人进步、完成改进和作品成果。平均分、最高分、次数排行降为辅助信息；若保留成绩比较，应限于可比任务并允许学生选择是否展示。教师首页突出“哪些学生在哪个任务卡住、需要哪种帮助”，而不是以低均分排列学生。

证据：[阅读即 100 分](/Users/laozhenyu/Project/interview/app/routes.py:1754)、[教师花名册](/Users/laozhenyu/Project/interview/app/routes.py:825)。

## 4. 建议补充的功能

| 优先级 | 功能 | 学生具体做什么 | 最小实现方式 |
|---|---|---|---|
| P0 | 岗位能力模板 | 看懂岗位日常、自己要练什么、怎样算完成 | 岗位说明增加培养阶段、核心任务、能力项、评价清单和适用规则版本 |
| P0 | 工作情境任务 | 确认不清楚的指令、交接工作、报告异常、回应客户 | 复用文字／语音对话，每个场景配置任务目标、角色、信息、关键行为和验收要求 |
| P0 | 针对性补练 | 针对报告缺口重答，随后完成新情境 | 报告生成一至两项训练任务，保留首次、修改及迁移验证结果 |
| P0 | 教师任务与反馈 | 接收班级任务、提交、根据老师反馈重做 | 任务发布、提交记录、评价清单、批注、退回和再次提交 |
| P0 | 线下实操证据 | 在实训中完成岗位操作、提交记录或作品 | 教师观察清单、作品附件、实训记录；操作是否达标由教师确认 |
| P1 | 上岗适应训练包 | 学会报到、确认任务、填写记录、交接、求助 | 按学校和岗位编排“第一天／第一周／第一个月”任务，不作为统一企业流程 |
| P1 | 基础工作与数字工具任务 | 写工作消息、看工单、核对数量、填表、查找操作说明 | 使用与岗位有关的短任务与交付物，不要求所有学生学习编程或复杂办公工具 |
| P1 | 能力证据档案 | 展示自己完成过什么，以及如何改进 | 汇集作品、实训表现、证书和评价，学生决定哪些内容进入简历或对外展示 |
| P1 | 实习反馈 | 对照真实工作记录问题，与教师／师傅讨论改进 | 简短的周记录、导师观察、改进任务、跟进状态；先支持教师代录，后加企业角色 |
| P2 | 真人协作任务与岗位探索 | 小组完成交接、分工和共同交付；了解其他岗位 | 可先复用课堂活动及现有岗位库，后续再开发多人任务、企业参访记录等 |

工作情境不能只有“你会怎么办”的口头回答：应让学生实际发送交接消息、填写工单、整理检查清单或提交作品。AI 可以模拟主管、同事或客户，但多人协作能力还需要真实课堂或工作观察。

安全、工作边界与求助应贯穿任务：不知道时如何确认、发现危险或质量异常时如何报告、超出权限时向谁寻求帮助。内容由学校及专业教师审核，按岗位规范设置。岗位适应力应包含合理表达问题和求助，不能把盲目服从或忍受不合理要求设为高分标准。

设备操作、维修、护理等实践能力不应仅凭聊天回答或单帧图像判定。平台负责组织、记录和反馈；专业教师或实习导师负责相应实操确认。后续视觉辅助评估也应先在具体任务上验证。

## 5. 一个可直接用于试点的情境

通用任务：“交接前发现一项工作还没有完成，接班同学只剩五分钟就要开始下一项任务。”

学生看到三项任务状态，向 AI 接班同学发送交接说明；对方问缺失信息，学生补充；学生再提交一张交接单。情境中的专业内容替换为相应工种的教师审核材料。

评价观察：

1. 是否区分已完成与未完成事项。
2. 是否说清当前状态、异常及影响。
3. 是否说明下一步、负责人和需要的支持。
4. 是否确认接班人理解，而不是只说“我交代过了”。

反馈示例：“你说清了已完成事项，但没有交代未完成事项的负责人。请补一条消息说明谁负责、什么时候处理。”

随后换一组任务状态，在无提示条件下再交接。首次、补练、换情境三次记录都保留。状态可为“需提示完成／独立完成／换情境仍能完成”，另设“未评估”。这些是试点评价方式，最终级别与达标规则由教师校准。

这种任务同时训练沟通、责任意识与工作组织，且能留下可检查的成果；具体专业操作另在线下实训验收。

## 6. 第一版建设顺序

第一步：修正评价和定位。统一岗位及轮次文案，移除固定技术招聘建议；未评估不计零分；分开阅读、测验和实操状态。

第二步：选一个专业、一个培养阶段、一个班级做小范围试点。由教师先定义三项关键能力，例如“确认任务、工作交接、异常求助”；每项准备初练、补练及不同情境验证。不要先扩建大题库。

第三步：打通“教师发布 → 学生完成 → 反馈 → 补练 → 新情境验证 → 教师确认”的完整流程，并支持至少一种线下实操记录。学生首页显示本周任务和待改进项，完成后再推荐下一项。

第四步：依据试点结果增加上岗训练、作品档案、实习导师反馈，再扩展其他专业。教师内容配置和复用是规模化前提，不能依赖每位教师反复写长提示词。

第一版验收应检查：任务实际可进入；提交和修改可追溯；未评估不会污染画像；教师能看到学生卡在哪一步；换情境能单独测评；线下证据可由教师确认。仅显示“完成”和提高 AI 总分不算完整验收。

## 7. 培养效果必须另外验证

本次未发现足以证明“AI 面试得分提高能迁移到实习表现”的学生效果数据。仓库中的模型模拟、提示词和软件回归测试可验证系统行为，不能代替教学成效验证。

建议优先检验三个假设：

- 学生能理解情境题，并在任务里采取适当行动，而不只是记住示例。
- 教师能使用发布与反馈流程，其工作量在可接受范围内。
- 在线训练的改进能在新情境或线下实训中继续出现。

先用一个班级观察流程问题，试点前约定评价清单、换情境测评方法和教师工作量上限。小样本能发现可用性和教学流程问题，不足以证明普遍成效；若要声称培养效果，需要可比前后测、适当的对照安排及更完整观察。

首要结果指标可用“同类新情境下，无提示独立完成关键行为的学生比例”，并分别报告教师确认的线下达标情况。辅助观察补练后的再次出错、任务流失和教师反馈耗时。真实实习评价作为长期校验，面试次数、平台使用时长和平均 AI 分数作为过程指标。

首要三项优先级：纠正评价含义；建立真实工作任务与补练；让教师和线下实训进入证据闭环。
