# 移动端模拟面试故障修复

2026-10-07（Asia/Shanghai）。用户截图为 iPhone 公网 HTTP 访问，显示 `NaN:NaN`、文字提交后“连接中断，请重试”和未恢复的等待状态。

## 定位结果

- 计时器把 Python 带微秒日期转为斜杠日期后交给 `new Date()`。用 `2026-10-07 20:36:12.123456` 实测：Chromium 可以解析，WebKit 返回无效日期。与截图一致。
- 公网 HTTP 属于非安全上下文，手机浏览器无法请求麦克风。前端代码无法代替可信 HTTPS。参考 [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。
- 旧文字逻辑遇到任何非 2xx 响应均显示同一句“连接中断，请重试”，且不清除播报区域的等待提示。截图意味着请求收到非成功状态，但不包含具体状态码或服务端错误，尚不能确定线上文字请求的最终原因。
- 公网 `/readyz` 正常；使用空闲测试账号登录后提交空文字进行无写入校验，接口返回预期的 `400 / Message is empty`，说明本次探针的登录和 CSRF 校验通过。测试账号已退出。未向线上面试提交回答。
- 现有 SSH 配置尝试连接时返回认证失败，未取得服务器日志，未部署本次修改。

## 本地修改

- 服务端计算面试已进行的秒数，前端即时显示并持续计时；刷新后从服务端恢复。不依赖设备时区、日期解析，超过一小时也不回绕到零分钟。
- 区分文字接口 JSON 错误、HTTP 状态、登录失效与 CSRF 失效；拒绝请求时恢复回答和草稿并解锁发送。
- 保留流式文字处理，兼容 CRLF、跨分包中文和无 Fetch reader 的读取路径。
- 识别流错误、缺少结束事件和 90 秒超时；恢复输入并更新状态。已被服务端接收的回答不会自动重发，以免重复写入。
- 麦克风授权、音频初始化阶段增加 30 秒超时；用户切回文字或超时后，迟到的授权结果也会释放麦克风。
- HTTP 页面常驻显示麦克风的 HTTPS 要求；语音点击时明确提示，保持文字入口可用。移除旧的 Chrome flags 引导，说明手机正常访问方式。

## 验证与后续

浏览器回归共 36 项通过，覆盖 Chromium / WebKit 下的计时、文字请求错误恢复、草稿刷新保留、中文流式回复、无 reader 回退、超时、HTTP 语音提示、语音采集与切换、迟到授权的麦克风释放。后端相关回归共 61 项通过。语法检查、关键 flake8 检查与 `git diff --check` 通过。

WebKit 测试需要将麦克风替身安装到 `MediaDevices.prototype`；原测试的实例赋值在 WebKit 后续调用中未生效。这是测试环境问题，修正后两种引擎的实时语音流程均通过，服务端语音供应商连接在该浏览器测试中采用模拟 WebSocket。

线上后续需要有效的服务器连接方式，读取失败请求对应的日志及状态码，再发布并验证；恢复手机实时语音还需要可供手机正常访问的可信 HTTPS 入口。浏览器自动化不等同于真实 iPhone 的麦克风硬件与蜂窝网络验证。
