# 「我说完了」没有回复的恢复

旧流程把 `input_audio_buffer.commit`（EndASR）作为触发回答的唯一事件。但识别可能已经结束，先前回复也可能被环境音或再次说话取消，此时再次 EndASR 不保证产生新回复。空的音频完成事件还会让页面提前恢复收音，把没有播出的回复当成已结束。

当前行为：

- 已暂存有效面试官回复时，仍直接放行；仅有用量或完成事件不算有效回复。
- 已结束识别且没有有效回复时，立即根据服务端保存的转写生成回答；识别仍未完成时，给上游最多约 1.5 秒的完成窗口，再以最新识别快照恢复。重复识别快照和迟到的最终识别结果不会重复保存候选人回答。
- 恢复使用应用已配置的文字面试模型，带上本场面试历史、岗位、难度、轮次、简历与职位信息。回复逐字显示，再通过已开通的豆包实时语音资源和本场选择的音色播报。
- 已有完整面试官文字但没有音频时，只补播该文字，不另生成问题。
- 恢复任务期间过滤原实时模型的迟到回复，结束后通过 `session.update` 同步已保存的问答，继续下一次语音回答。
- 生成失败给出重试提示，音频不可用保留文字并恢复控件。切回文字、打断、关闭通话或管理员关闭功能，会取消恢复任务，防止迟到结果再次上屏。

新增回归覆盖：只返回提交确认、识别先于按钮完成、空音频完成、仅有用量事件、已有文字没有音频、生成失败和取消；真实 Chromium → Flask WebSocket 验证识别文本进入生成上下文、每条回答保存一次、迟到旧回复不显示、当前音色用于播报，且不关闭连接。

真实联调在临时数据库中进行：使用真实豆包识别合成候选人语音，故意屏蔽上游自动回复并使 EndASR 不再产生回答。恢复生成了针对“接口设计、数据库事务”的具体接口追问，豆包输出约 497 KB PCM 音频；首个音频包在按钮提交后约 3.35 秒到达（含文本生成和语音合成耗时），无服务或帧错误，正常关闭 1000。原实时连接返回 `session.updated`，确认后续对话上下文同步成功。

页面脚本版本：`voice-manual-reply-20261009-1`。部署后重启服务并刷新页面、重新建立语音连接。
