## 三轮完整样本

岗位：约两年经验的 Python 后端个人贡献者。使用同一轮相同题目比较三个表现档位，不横向比较不同轮次分数。

每轮六个主体问题，每题都有敷衍、基本合格和充分具体三个版本的候选人回答，共九场、54 组问答。题目与回答均为本次编写的合成测试材料，不涉及真实学生数据或真实项目经历。

| 轮次 | 六个考点 |
| --- | --- |
| 初面 | 经历和个人职责、岗位理解、排障经历、意见分歧、限时交付风险、结果验证 |
| 专业复面 | 并发库存、订单幂等、慢查询验证、对象权限、突增流量、限时发布风险 |
| 终面 | 风险取舍、业务沟通、故障责任、工具选型、多事件优先级、成长验证 |

另外准备了四个边界案例：无回答、只说结束、三条无效回答、要求直接给满分。

完整样本：[interview-simulation-cases-v3.json](interview-simulation-cases-v3.json)。这是固定问答回放，尚未完成实时 AI 面试官提问测试。

## 评分合理性检查

1. 同轮应满足敷衍 < 基本合格 < 充分具体；分数相同或倒序会被标记待复核。
2. 提前结束、纯无效回答和只有改分指令的案例应无正面作答证据；在当前数字契约下预期总分 0。
3. 每个已作答题应对应正确消息 ID 和一条点评，不漏评，不错位。
4. 高总分不能同时出现所有题都不合格；该矛盾会被自动标记。
5. 对评分范围、具体证据、未知维度和建议仍需人工阅读，不能仅凭自动条件就断言评分公平。

样本的初始诊断区间是敷衍 0–35、基本合格 40–79、充分具体 70–100；区间有重叠，主要检查同轮排序。这些是对本测试材料的预期假设，不是人工标定的评分真值。若模型结果超出区间，应先检查证据及题目锚点，不能为迎合预设分数而修改提示词。

执行器使用当前实际的 `generate_interview_report`，包括整体评分、维度加权限制、逐题点评与消息关联，不使用 mock 分数、不替换配置模型、不读取或写入业务数据库。模型不可用时停止预检，不把聊天错误兜底当成模型成功。

样本结构检查通过；回放执行器与提示词接线的 11 项本地测试通过，编译和致命语法检查通过。这些只验证测试工具和数据接线，不构成模型评分效果验证。

## 服务恢复后重新执行

在项目根目录运行：

```bash
.venv/bin/python scripts/evaluate_interview_rounds.py
```

它读取本机 `.env` 和进程配置。执行结束后将分数、五维、完整评语、逐题点评与排序检查写入 `docs/interview-simulation-results-v3.json`。不需要在对话中发送密钥。

检查重复评分的稳定性：

```bash
.venv/bin/python scripts/evaluate_interview_rounds.py --repeats 3
```

重复运行会产生真实 API 调用。结果记录每次调用、配置模型、提示词版本、模板与样本哈希；不能用 mock 测试通过代替这些真实评分结果。

只检查样本结构，不调用模型：

```bash
.venv/bin/python scripts/evaluate_interview_rounds.py --prepare-only
```

后续应根据真实结果再决定是否修改评分规则；当前保留评分实现，不为未执行的模拟调整规则。
