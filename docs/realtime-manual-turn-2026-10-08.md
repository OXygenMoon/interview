# 实时语音手动结束本次回答

实时语音控件新增「我说完了」。候选人已说完但环境音持续触发声音检测时，可点击按钮提交本次回答，跳过应用的 3 秒静音等待，不关闭 WebSocket 会话。

浏览器立即暂停上传，服务端向豆包发送 `input_audio_mute.commit` 保持连接。若回复已生成但被静音等待拦住，则直接释放暂存的文字和音频；否则发送 `input_audio_buffer.commit` 强制结束识别。提交期间忽略迟到的麦克风帧和识别进度，重复点击不会再次提交。

按钮在连接准备完成前不可用，提交后显示「等待面试官」。面试官音频实际播放结束后恢复上传并重新启用按钮；保留用户原有静音选择。点击「打断面试官」可提前恢复，切回文字或停止通话会清理提交状态和计时器。若服务端长时间未回应，页面恢复收音并提示重试。

持续环境音会延长自动静音等待，但不会反复取消同一段暂存回复。恢复声音活动后取消暂存回复的条件改为新的声音起始，ASR 新回答仍可触发取消。自动 3 秒等待的原有行为保留。

验证：

- Chromium 实际 AudioWorklet 使用连续振荡器模拟环境音，在桌面与 390 px 手机页面连续完成两次手动提交；等待及播放期间没有继续上传，音频全部播完后恢复同一个麦克风和 WebSocket，控件无横向溢出。
- Chromium → Flask → 模拟提供方验证强制提交、重复提交与迟到帧过滤，两次回答和追问各保存一次；自动静音等待、短暂停顿继续回答、WebSocket 关闭及帧传输回归通过。
- 真实豆包服务测试：合成候选人语音叠加连续环境音，等待约 4.5 秒仍未放行回复；手动提交后首个暂存音频包约 5 ms 到达浏览器，无服务错误、无帧错误，正常关闭（1000）。此前强制结束未完成识别的实测首个音频包约 824 ms 到达。所有测试均使用临时数据库。

页面脚本版本为 `voice-finish-turn-20261008-1`。刷新并重新连接实时语音后生效。
