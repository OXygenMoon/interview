CODE REVIEW / 2026.10.05

先理清层级，再统一设计。

项目使用 Flask/Jinja 模板、Tailwind CDN、DaisyUI 4 与原生 JavaScript。已有面试设置、冷却提示、报告状态、学生首页和教师数据看板，适合在现有架构内逐步升级。本次审查聚焦四个页面文件；下列判断来自代码，未对正式环境的速度或转化率作测量。

需要优先解决的问题

01 / 高优先级：主题规则互相覆盖，影响后续迭代

学生与教师的基础模板都在模板内定义较长的 CSS，重复覆盖按钮、卡片、表单与导航。通用选择器带有大量 !important，会压过具体页面的视觉定义。学生首页的多色卡片与基础模板的统一表面覆盖也存在表达冲突。

证据：app/templates/base.html:179–240；app/templates/teacher_base.html:175–238。

建议：先抽取表面、间距、字号、圆角与颜色变量，建立学生端和教师端两组主题；使用页面作用域降低覆盖，不一次重写业务模板。

02 / 高优先级：基础模板加载的资源缺乏页面边界

学生端每个页面都加载 Tailwind CDN、DaisyUI、Markdown 解析、图片导出和 PDF 导出脚本；图片和 PDF 脚本即使在不需要导出的首页也会加载。部分脚本 URL 不包含固定版本。首屏样式和功能可用性由多个外部资源共同决定。

证据：app/templates/base.html:8–13；教师端同样使用 CDN 样式，见 app/templates/teacher_base.html:8–10。

建议：继续使用现有 Tailwind/DaisyUI，固定资源版本并构建本地样式；只在报告等需要的页面加载导出脚本。实际优化幅度需通过真实网络和性能测量验证。

03 / 中优先级：首屏的视觉强调过多

首页同时使用大面积橙黄渐变、背景光晕、玻璃侧栏、多色统计卡片和悬停动画；教师 Dashboard 又使用青、蓝、黄、紫多组强调色。开始面试、统计信息与知识入口的强调力度接近。

证据：app/templates/index.html:22–120；app/templates/dashboard.html:12–106。

建议：学生端围绕「继续练习 / 先复盘」组织首屏；教师端优先显示需要处理的异常和学生表现变化。选一组稳定主题，把语义色留给状态。

04 / 中优先级：输入与网络错误依赖系统弹窗

岗位为空、创建失败、网络失败和冷却限制采用 alert()。输入问题会打断操作，网络错误与恢复入口没有直接呈现在表单中。

证据：app/templates/index.html:566–591、623–636、657–675。

建议：岗位错误显示在输入框旁；请求失败保留已填信息并提供重试；冷却状态保留现有横幅，直接说明剩余时间与复盘入口。继续保留已有处理中与报告失败状态。

05 / 中优先级：键盘与移动端细节可以补齐

两个基础模板的移动菜单按钮只有图标，没有可访问名称，也未声明菜单展开状态；模板内未显式定义按钮和链接的焦点样式，以及减少动态效果的规则。主区域使用 100vh。数据表使用水平滚动，信息优先级还可以优化。

证据：app/templates/base.html:167–170、270–280、391–420；app/templates/index.html:131–145。DaisyUI 可能提供部分默认焦点样式，正式页面仍需逐项检查。

建议：增加菜单名称、aria-expanded 和 aria-controls；提供键盘可见焦点、跳转到主要内容的链接与减少动态效果选项；移动端优先展示岗位、得分、状态与操作。

十套方案，如何选择

方向 排版结构 适合的产品体验
01 企业工作台 ↗ 固定侧栏 + 非对称分析区 高频使用、导航清晰的正式平台
02 编辑杂志 ↗ 报刊头版 + 衬线标题 + 三栏正文 注重个人叙事与成长复盘
03 终端控制台 ↗ 顶栏 + 高密度方形面板 + 诊断日志 技术人群、数据感较强的训练工具
04 先锋粗野主义 ↗ 巨字分屏 + 硬边与偏移阴影 强调行动和鲜明品牌记忆
05 自然极简 ↗ 开放双栏 + 圆环 + 日常练习清单 缓解面试紧张、建立长期习惯
06 午夜玻璃 ↗ 悬浮图标导航 + 不规则玻璃面板 沉浸的个人空间和深色界面
07 柔彩创意 ↗ 图形首屏 + 彩色卡片 + 宽松分组 学生人群、温和的练习陪伴感
08 瑞士国际主义 ↗ 严格网格 + 巨大数字 + 线条分区 清晰、有秩序、品牌识别度较强
09 计划看板 ↗ 工具侧栏 + 三阶段可拖动任务列 将面试准备组织成可推进的计划
10 经典学院 ↗ 目录侧栏 + 研习章节 + 能力评估 职业教育、学院或专业训练平台

从当前产品形态出发，建议先用 01 测试导航与信息效率，再比较 05 的训练引导、09 的任务组织和 10 的学习结构。其他方向可用于探索更鲜明的品牌表达；最终选择应结合真实用户反馈。

建议的升级顺序

  1. 选定视觉方向，定义颜色、字体、间距、按钮和状态规范。
  2. 抽取公共样式与导航，整理资源加载；保留 Flask/Jinja 与现有 API。
  3. 先升级学生首页的开始、冷却、复盘和失败恢复流程。
  4. 再升级教师看板，区分汇总指标、异常记录和需要关注的学生。
  5. 用真实内容检查桌面、手机、键盘导航和长文本，运行核心业务回归。

本次测试区的边界

十套页面均使用本地示例数据。面试设置、固定示例反馈、报告阅读和看板操作用于交互预览，不创建真实面试、不读取账号、不调用 AI。收藏保存在当前浏览器，任务调整只在当前页面有效。正式界面保留原样，选定方向后再逐步接入真实数据和业务状态。
